# Go の並行処理

## goroutine の起動

うちの決済サービスでは、goroutine を起動する箇所に、止め方をコメントで書くのがルール。
ループの中で起動するときは、使う値を引数で渡す書き方にそろえている。
起動しっぱなしのものがないか、四半期に一度コードを見直す日を設けている。
新しく入った人には、最初のレビューでこのルールを説明する。

## channel でやり取りする

チームでは、goroutine 同士の受け渡しは channel に統一している。
close するのは送る側の関数だけ、という点をレビューで必ず確認する。
バッファの大きさは定数にして、その数にした理由をコメントに残す。
受ける側は range で読み切る書き方にそろえている。

## 終了を待つ

全部の goroutine が終わるまで待つ処理は WaitGroup で書き、Add と Done の位置をレビューで見る。
途中で止めたい処理には、必ず context を渡す決まり。
エラーをまとめて受け取りたいときは errgroup を使う。
待つ処理には上限の時間を決め、超えたらログを出して抜ける。

## データ競合

CI では、テストを -race 付きで毎回回している。
去年、同じマップを複数の goroutine から書き換えていて、集計がずれる障害を出した。
それ以来、共有する値は Mutex で守るか atomic を使うことにした。
並行処理を含むテストは、CI で十回くり返して流す設定にしている。
